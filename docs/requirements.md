# Требования

## Контекст

Сайт-приглашение на свадьбу **Вероники и Дмитрия** (26.12.2026), бренд **Ethereal Union**. Одна страница по макету Stitch: шапка с SVG-логотипом, неон-герой с таймером, приветствие, четыре карточки истории, золотой таймлайн программы, блок «Для гостей», подтверждение присутствия, локации и подвал.

Макет: `docs/stitch_modern_material_redesign/`. Вид: `docs/DESIGN.md` (Angular Material 3). Старые паттерны (shadcn, волна weddingpost, лонгрид Yami `#time-line`, dusty-rose `#C4A4A5`) не действуют.

Режим `full=true`: в программе есть торжественная регистрация 14:30, карточка локации **Регистрация** видна, виджет Яндекс.Карт полный. Без `full` регистрация скрыта и в расписании, и среди карточек локаций; виджет короткий. Карточка **Банкет** видна всегда.

Анкета подтверждения уходит в Google Cloud Run и дальше в Telegram. Других бэкендов нет.

Исходные тексты гостя — `docs/user-requirements.md` (не изменять). Виджеты: `docs/widget-full.html`, `docs/widget-short.html`.

Тихий редакционный слой движения (появление при скролле, короткий вход героя, bloom узлов таймлайна) не меняет тексты гостя, RSVP, `full=true`, слоты фото, логотип и порядок блоков.

### FR-15 Тихий слой движения
**Приоритет:** Must  
На одностраничном приглашении действует единый редакционный слой движения: короткое появление **opacity + translateY 8–16px**, длительность **400–700 мс**, easing **ease-out** (без bounce и overshoot). Срабатывает **один раз** при входе в viewport. Не меняет гостевые строки, RSVP, поведение `full=true`, слоты фото, логотип и порядок блоков FR-13. Не добавляет секций и не меняет русские тексты.

Запрещены: конфетти, циклические частицы, автоплей-видео, блёстки за курсором, прыгающие лоадеры, GSAP pin/sticky/parallax фона истории, AOS-зигзаг лонгрида. Без новых npm-библиотек анимации (не GSAP, не AOS, не Lottie на всю страницу). Реализация: **CSS + Intersection Observer** (без CDK Overlay).

Сохраняются уже существующие: цветовые hover-переходы ссылок шапки; `html { scroll-behavior: smooth }` (якоря `#story`, `#program`, `#details`, `#rsvp`, `#locations`); bloom узлов `.timeline-node` / `.timeline-node--bloom`.

### FR-16 Вход героя
**Приоритет:** Must  
При загрузке в `#home` короткой последовательностью появляются уже существующие элементы (не новые тексты): kicker `.hero-kicker` («Приглашение на свадьбу»), имена `#hero-heading.neon-invitation`, дата `.hero-date`, затем ряд `.countdown-row` / плитки `.countdown-tile`. Общая длительность последовательности **не больше 1 с**; не театральное интро ≥ 2 с и не блокировка чтения. После последовательности все перечисленные элементы в конечном видимом состоянии.

Смена цифр таймера — обычная подстановка текста в `dd` плиток; без 3D-переворота, flip-цирка и анимации, из-за которой цифра нечитаема. Допустимо едва заметное «дыхание» многослойного `text-shadow` только у `#hero-heading.neon-invitation` (период **≥ 6 с**, без сдвига layout и без изменения кегля); **не** применять к `.countdown-tile` и цифрам.

Маркеры состояния (для приёмки): элементы входа несут класс **`motion-hero`** и после появления — **`motion-hero--in`**.

### FR-17 Появление блоков при прокрутке
**Приоритет:** Must  
Ниже первого экрана блоки получают класс **`motion-reveal`** и после пересечения viewport — видимое состояние **`motion-reveal--in`**. Пока не пересекли порог, декоративно скрыты (opacity 0 + лёгкий translateY), место в потоке зарезервировано (без схлопывания высоты). После появления **не скрываются снова** при уходе из кадра.

Цели (существующие селекторы, без новых копирайтов):

- приветствие: `#welcome-heading` и абзац секции приветствия;
- сетка истории: четыре `#story article.gilt-card`, stagger **80–120 мс**;
- программа: секция `#program` (заголовок и/или список слотов);
- детали: `#details article`, stagger **80–120 мс**;
- анкета: секция `#rsvp`.

После перехода к якорю шапки (`#story`, `#details`, `#rsvp`, `#locations`) целевые блоки видимы (opacity > 0 и класс **`motion-reveal--in`**). Локации и подвал могут использовать тот же паттерн, но не обязаны, если это не ломает вёрстку.

### FR-18 Bloom узлов программы
**Приоритет:** Must  
На ширине **md и выше** (≥ 768px) в `#program` узлы `.timeline-node` — круги **8px** real-gold `#D4AF37`. Когда слот попадает в зону видимости, у узла есть **`.timeline-node--bloom`**: мягкое powder-pink `#F4C2C2` свечение (как сейчас в `src/styles.css`). На узкой ширине узлы по-прежнему скрыты (`hidden md:block`) — не регрессировать. Поведение `full=true` / короткий таймлайн FR-06 не меняется.

### NFR-09 Запуск
**Приоритет:** Must  
`npm start` → `http://localhost:4200/`. Режим и предзаполнение — query.

### NFR-10 Движение и доступность
**Приоритет:** Must  
При `prefers-reduced-motion: reduce`:

- декоративное движение **не запускается** (нет входа героя, нет fade/rise, нет дыхания неона, нет transition bloom);
- контент сразу в **конечном видимом состоянии** (opacity 1, без translateY, без задержки): `#hero-heading`, `.countdown-tile`, карточки `#story` и `#details` после перехода к якорю видны без ожидания анимации;
- `html { scroll-behavior: auto }` (как уже в `src/styles.css`);
- у `.timeline-node` нет transition; узел остаётся видимым золотым кругом 8px.

Не анимировать `outline` (в т.ч. не убирать `:focus-visible`). Движение не даёт скачка вёрстки (CLS): только **opacity** и **transform**, высота блока не анимируется. Цифры таймера читаемы при каждой смене секунды.

### NFR-11 Производительность слоя движения
**Приоритет:** Must  
Только CSS и Intersection Observer; **без** новых npm animation-фреймворков. Не ломает раскладки **390** и **1920**, не добавляет горизонтальный скролл документа (NFR-04 остаётся в силе). Hover ссылок шапки и bloom `.timeline-node--bloom` не пропадают на обычных настройках motion.
