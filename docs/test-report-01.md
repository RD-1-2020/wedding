## Эталон Love Story (Yami-Buzzy #gift)

**Важно для аналитика:** hash `#gift` ведёт в блок подарков (`#gift.section-gift`, QR, «SENDING GIFTS…»). Паттерн Love Story на этой же странице — секция `#time-line` (`Our Love Story`), сразу после таймлайна дня `#dresscode`. Именно её нужно фиксировать в FR/AC.

Наблюдаемые факты `#time-line`:

- Один лонгрид, не набор карточек со своими фонами.
- **Один** фоновый кадр на всю секцию: `background-image: url(…/8430.webp)`, `background-size: cover`, `background-position: 50% 50%`. Это другой кадр, не дубль квадратов таймлайна.
- `background-attachment: scroll` — фон **не** `fixed`, **не** sticky и **не** pin/GSAP. Параллакса нет: фон едет вместе со секцией, пока гость листает годы.
- Затемнение: класс `bg_overlay` на той же секции; текст и линейка белые, фон читается как размытый/притемнённый городской кадр.
- Высота лонгрида растёт с числом вех: desktop ≈ 2500×1280, mobile ≈ 1205×390.
- Поверх фона — вертикальная **белая** ось по центру (тонкая линия на всю высоту таймлайна).
- Вехи **чередуются зигзагом**: фото слева / текст справа, следующая — фото справа / текст слева (классы элементов таймлайна + `data-aos="fade-up"`).
- Квадратные фото вех: исходник **500×500**, `object-fit: cover`, `border-radius: 8px`, тёплая коричневая/медная рамка. На desktop рисуются ≈ **456×456**, на mobile ≈ **139×139**. Sticky/pin у фото нет (`position: static`).
- На эталоне **пять** вех (2020 First Meeting … 2024 Proposal Day), у каждой: год (крупный serif), короткое название, одна строка подписи. Заголовок секции: «Our Love Story», `Noto Serif Display`, 54px, weight 700, белый, по центру. Подписи — `main-font` 16px белые.
- Появление: AOS `fade-up` при скролле, не отдельный экран на каждый год.
- Мобилка: тот же паттерн (один фон + ось + зигзаг), квадраты меньше, текст остаётся белым на оверлее.

Что **не** является Love Story на этом сайте (не путать при переписывании FR):

- `#gift` — подарки/QR, градиент powder→white, без лонгрида.
- `#album` / `#wedding-gallery` — 3D coverflow/swiper портретов на белом фоне (это галерея, не история).
- `#dresscode` — программа дня: тёмно-коричневый сплошной фон, белая ось, иконка слева / время+название справа. Это расписание, не Love Story.

## Эталон расписания (weddingpost invent 1163, mobile)

URL с `mode=mobile_preview`. После загрузки («Загрузка приглашения») секция `#timetable` / «Свадебное расписание» — внизу длинной страницы (~y 5200).

Наблюдаемые факты программы:

- Не список в карточке и не горизонтальный таймлайн. Это **вертикальная волна**: тонкая тёмная S-кривая по центру (`tt-wave-left` / `tt-wave-right`), события чередуются по сторонам.
- Фон секции — кремовая «бумага» (текстура акварели/пергамента), не золотые карточки и не пыльный розовый.
- Заголовок «Свадебное расписание» / «СВАДЕБНОЕ РАСПИСАНИЕ»: тонкий элегантный serif, приглушённый серо-коричневый, по центру, много воздуха сверху.
- Каждое событие — блок ≈ 333×162: **время сверху**, затем название, затем короткая серая курсивная подпись. Адрес в разметке есть (`.tt-event__address`), на mobile `display: none`.
- Время: `CormorantInfant-Bold`, ≈ 27px, weight 600, чёрный. Чётные вехи (`tt-wave-left`) выравнивают время/текст **вправо**, нечётные (`tt-wave-right`) — **влево**.
- Название: тот же семейство, ≈ 19px. Описание: `Magnolia`, ≈ 11.5px, `rgb(128,128,128)`.
- Напротив текста — тонкая линейная иконка (кольца, бокалы, камера, клош), не фото и не цветной бейдж.
- На кривой — маленькие тёмные точки; одна точка заменена **бежево-золотым сердцем** (единственный явный золотой акцент внутри таймлайна).
- Золотые «карточки» и золотые линейки-разделители в самой программе **не** используются. Золото на этом макете живёт в шапке (кнопка «Добавить в календарь», `rgb(187, 173, 123)`) и в календаре выше по странице (рамка, сердце на дате).
- Стек на mobile: одна колонка, события друг под другом с ровным вертикальным ритмом (~162px шаг), без горизонтального скролла.
- Состав эталона (не наши слоты): 12:00 Торжественная регистрация → 14:00 Фуршет → 17:00 Праздничный банкет → 23:00 Окончание праздничного дня.

## Сравнение с текущим сайтом (localhost:4200)

Сайт открылся. Герой уже близок к приглашению (фото пары на весь экран, дата, таймер). Отличия по двум целевым блокам:

- **Love Story сейчас:** сплошной тёмно-коричневый фон (не одно фото с оверлеем), заголовок + короткая золотая линейка, одно квадратное фото в толстой золотой рамке. Нет белой оси, нет зигзага фото/текст, фон не тянется как лонгрид по годам.
- **Программа сейчас:** кремовая карточка, золотые круглые буллеты, одна колонка «название + время в той же строке» (банкет 15:30 / торт 21:30 / окончание 22:30), кнопка календаря внутри карточки. Нет S-кривой, чередования сторон, времени как крупного левого/правого акцента, иконок и бумажной текстуры 1163.

## Итог

Аналитик должен переписать требования так:

1. **Love Story = паттерн `#time-line` Yami-Buzzy** (не `#gift`, не 3D-альбом): один лонгрид, один cover-фон с затемнением, белая центральная ось, ровно три наших квадрата 512×512 (2022 / 2023 / 2026) зигзагом поверх фона, год + подпись, появление по скроллу. Фон не `fixed`/pin.
2. **Программа = паттерн weddingpost invent 1163 mobile:** вертикальная волна на кремовой бумаге, время крупным serif с чередованием лево/право, название + короткая строка, линейные иконки напротив текста, точки на кривой и один золотой акцент-сердце; не список в карточке с буллетами. Состав слотов и кнопка календаря — по нашим FR, оформление — по этому макету.

Полный pass/fail старых US в этом прогоне не ставился: цель — фиксируемые наблюдения эталонов.
